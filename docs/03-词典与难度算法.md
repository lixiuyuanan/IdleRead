# 03 · 词典与难度算法

闲读的“难度”不是一个标签，而是两套互补的规则：

- **选词**：正文里哪些词该划、哪些算已掌握 —— 决定用户看到什么；
- **定级**：一篇文章该放进哪一档 —— 决定用户从哪读起。

两者共用一套词表（词频 + 考试标签），但用途不同，不能混为一谈。

---

## 一、词表数据

```js
dict["abandon"]  = ["ə'bændən", "vt. 放弃，抛弃", 1203, "zk gk cet4"];
//                   音标        中文释义         词频排名  考试标签
lemma["abandoned"] = "abandon";
```

- `rank`：通用语料词频排名，`0` 表示没有可靠排名；
- `tags`：空格分隔，可能包含 `xx zk gk cet4 cet6 ky toefl ielts gre`；
- 音标统一转写为 IPA：ASCII `'` → `ˈ`，旧式 `.`/`,` → `ˌ`，`ɒ → ɔ`；
- 词条键一律小写；固定短语（含空格/冒号）作为完整键，不拆。

当前规模（2026-10-30）：**66,503 词条、39,130 条词形、14,618 个语料词头全部可查**；空释义 0、无中文 0、断词形 0；空音标 4,170（6.27%，多为缩写、专名与极冷词）。

## 二、查词链路（`headOf` → `dictEntry`）

同一个词在文中可能以任意形态出现，查表前要先归到词头：

```
原文 surface
  ↓ 小写、弯撇号→直撇号、去 's
  ↓ 缩写还原：we'll→we、don't→do（CONTRACT 表；'ll / n't 走规则剥离）
  ↓ 原始键不存在时折叠重音：cliché→cliche、Ødegaard→odegaard
  ↓ 查 lemma.json；命中且不是已知错项 → 用原形
  ↓ 否则查词典本身（带词频或考试标签的条目直接认）
  ↓ 否则按后缀试还原：-ies/-es/-s/-ed/-d/-ing/-er/-est，双写辅音去一
  ↓ 候选必须“本身有词频或考试标签”才算命中，防止 rent→rend 这类误归
head
```

关键防错：

- `BAD_LEMMA`：`feed→fee`、`number→numb`、`does→doe`、`rent→rend`、`ground→grind` 这类机械还原会查错词，显式拦掉；
- `own()`：所有查找只认自有属性。词典里确有 `constructor`，直接 `DICT[k]` 会拿到 `Object.prototype` 上的函数，界面上会显示 `function Object() { [native code] }`；
- 重音折叠只在原键不存在时发生：`café` 若词典里真有，就不折成 `cafe`。

## 三、句内词性：为什么需要

一个词条常有多个词性（`record` 名词/动词、`well` 副词/形容词）。词卡默认显示全部释义，但**正文朗读、例句、划线判断**需要知道这里到底是哪一类。

`guessPos(sent, word)` 不训练模型，用可解释的规则：

1. 按标点和虚词切出名词短语；
2. 判断目标词是短语中心词还是定语；
3. 看左侧：冠词/形容词/介词 → 名词；情态动词/助动词 → 动词；
4. 看右侧：`to` + 动词原形 → 动词不定式；`-ing` 前有 be → 进行时；
5. 相邻词互相校验：并列结构（and/or）两侧词性一致；
6. 拿不准就返回空，界面不做强判断。

这部分规则在 `app.js` 的“句内词性”区块，注释里逐条写了触发条件；`tok_probe.py` 会验证分词坐标与词性边界没有被改坏。

## 四、分档：哪些词算“学过”

### 标签顺序

```js
TIER_ORDER = ['xx', 'zk', 'gk', 'cet4', 'cet6', 'ky', 'toefl', 'ielts', 'gre'];
```

`xx` 小学、`zk` 中考、`gk` 高中、`cet4` 四级、`cet6` 六级；`ky/toefl/ielts/gre` 参与“是否已分级”，但不作为学习目标档。

### 已掌握

```
已掌握 = 词频 ≤ 800
        ∪ 带“目标档及以下”任一标签
        ∪ 用户手动标“已掌握/已忽略”
```

词频保底是必须的：教材基础词（farm / sheep / pig）在通用语料里排名很靠后，只靠标签会把它们当生词。

### 正文划线（本档新增词）

```
本档新增 = 带本档标签，且不带任何更低档标签
```

例如目标“高中”：`xx`/`zk` 词不划（已掌握），`gk` 词划线，`cet4` 以上的词也不划（还不是当前任务）。

### 求索

```
求索 = 不带任何分级标签（xx…gre）的词
```

“求索”不是“最难档”，而是“词表之外的词”：新词、专名之外的生僻词、未被任何考纲覆盖的词。这样划线不会重复，也不会把四六级词当成“未知”。

### 用户反馈覆盖

- 标“不会” → 强制算生词，划线；
- 标“已掌握/忽略” → 强制算已掌握；
- 复习通过 3 次以上 → 即使不在表内也算已掌握；
- 点过但未通过 → 只有连续失败、且不在表内时才持续划线。

这套状态同时驱动复习卡的阶段（初遇/再见/熟识/掌握）与正文虚线下划线（`hiTag`）。

## 五、SRS

四阶段 + 稳定度：

```
初遇 0.5 天 → 再见 2 天 → 熟识 8 天 → 掌握 21 天
答对：stab × 1.8（上限 365）
答错：stab × 0.6（下限 0.5）
间隔 = round(stab)；当天到期记为 0
```

复习池按 `due` 排序，例句取最近 15 条上下文。没有引入完整 FSRS：词量小、复习频率低，四阶段足够，且状态可以用一个 `stab` 数字解释。

## 六、文章定级

`tools/relevel_articles.py`：

1. 用文章在该档**累积词表**下的生词率：
   - 中考 = `xx + zk`；高中 = 再加 `gk`；四级 = 再加 `cet4`；六级 = 再加 `cet6`；
2. 取“生词率 ≤ 3.5%”的**最低档**；
3. 各档都不合适、但六级读者 ≤ 8% → 归六级（能读但吃力）；
4. 六级仍 > 8% → 课外；
5. 番外（0）与书架（90）不动；真题（带 `origin`）保留来源档位，只作校验真值，不参与写回。

生词判定与 App 完全一致：词频 ≤ 800 ∪ 累积标签；缩写先还原、变形先归原形、专名不计。若两处口径不同，用户在列表看到的“生词率”就会和定级结果矛盾。

### 双信号审计

`tools/audit_level_outliers.py` 不重复跑定级规则（那是循环论证），只回答三件事：

| 信号 | 指标 | 用途 |
|---|---|---|
| 信号 1：考纲生词率 | 每篇用它自己档位的累积词表量 | 档内中位数是否落在 2%–3.5% 的“合适带” |
| 信号 2：独立可读性 | Flesch Reading Ease、Flesch-Kincaid 年级、平均句长、≥7 字母长词占比 | 不依赖词表的第二把尺子 |
| 离群判据 | 档内稳健 z = (x − 中位数) / (1.4826 × MAD)，\|z\| > 2.5 | 找出“明显比同档难/易”的篇目 |

审计只出报告，不改数据。2026-10-28 的完整结果见 `reports/难度审计-20261028.md`。

## 七、词表构建流水线

以 **[ECDICT](https://github.com/skywind3000/ECDICT)（MIT 许可）** 为主源，[COCA](https://www.english-corpora.org/coca/) 词频为基线：

```
ECDICT CSV (77 万条)
  ↓ build_dict.py：选词（语料词全收 ∪ 有考试标签 ∪ 词频阈值）
  ↓ clean_dict_defs.py：释义按词性归并、去 [计][医] 领域标记、全角标点、截断
  ↓ restore_stress_marks.py：旧式 . / , → ˌ
  ↓ fill_dict_gaps.py：拼写变体（jobseeker→job seeker）、专名补条
  ↓ fill_phon_cmu.py：CMU 音素补缺失音标
  ↓ fill_phon_derived2.py：规则派生（复数/过去式/-ing/-ly/复合词）补音标
  ↓ align_published_dict.py：常用词释义以已发布版为准
  ↓ audit_dict_quality.py：可用性体检
dict.json + lemma.json
  ↓ build_mobile_data.py（需内容流水线）
assets/www/data/*.json
```

设计原则：

- **覆盖优先于精简**：语料里出现过的词头必须能查到，否则词卡会出现“未收录”；
- **不硬造释义**：OCR 乱码、新词只报告，不生成假释义；专名补“（专名）”条目，前端识别后不划线；
- **音标可缺不可错**：宁可留空，也不从错误的词形推导；
- **标签/词频只做对齐，不重算**：扩量时保留已有考试标签，避免用户的已掌握状态整体漂移。

### 三个质检口径

| 脚本 | 回答的问题 |
|---|---|
| `audit_dict_quality.py` | 每条能不能用：空释义、无中文、方括号、断词形、语料缺口、空音标率 |
| `lint_text.py` | 字符脏不脏：零宽字符、控制符、字面 `\n`、UTF-8 套娃、坏音标 |
| `dict_quality_probe.py` | 在真实页面里点开词卡：随机词头 + 中文反查 + 短语，不能出现“未收录” |

## 八、搜词排序（复习页）

英文：前缀匹配优先 → 固定短语整体匹配加权 → 词频/长度/字母序。

中文：反向检索释义，按以下顺序比较：

1. **是否整义项命中**：命中位置必须是义项开头（前一个字符是分隔符或空白），`美丽的` 这类派生后缀仍算；
2. **义项序号**：越靠前的义项越相关；
3. **难度分**：`max(考试档序号, floor(词频/3000))` —— 取“更靠后”的那个，让 `abandon`（高中、词频 14530）排在 `disclaimer`（GRE、词频 1558）前面；
4. 词频排名、释义长度、词长、字母序依次决胜。

索引首次查询时构建（6 万多条），之后常驻；本机实测首次约 20ms、后续 4–6ms。

## 九、已知边界

- 词表是静态数据，新词只能在下次重建时进入；
- 音标缺失集中在缩写、专名与极冷词，正文里这些词的词卡只显示释义；
- 词性规则覆盖常见句式，诗歌、标题、省略句会退回“不判断”；
- 中文反查是字符串匹配，不做分词，因此单字查询会命中较多结果，靠排序收敛。
