# 04 · 构建、测试与发布

---

## 一、环境

| 依赖 | 版本 / 说明 |
|---|---|
| Python | 3.10+ |
| Android SDK | build-tools **34.0.0**、platform **android-34** |
| JDK | 17（`javac` / `keytool`） |
| [GitHub CLI](https://github.com/cli/cli) | 发布用，需 `gh auth login` |
| Python 包 | [`websocket-client`](https://github.com/websocket-client/websocket-client)（探针）；[`eng-to-ipa`](https://pypi.org/project/eng-to-ipa/)（仅补音标脚本） |

路径通过环境变量指定，不写死：

```bash
export ANDROID_SDK_ROOT=/path/to/Android/Sdk
export JAVA_HOME=/path/to/jdk-17
```

Windows 下如果控制台是 GBK，所有脚本都要带：

```bash
PYTHONIOENCODING=utf-8 python tools/build_apk.py
```

否则脚本里的 `✓` 等字符会抛 `UnicodeEncodeError` —— 编译本身没失败，是打日志挂了。

## 二、构建前的数据

`assets/www/data/` 下的三个 JSON 不随源码提供：

```
articles.json   # 文章（含正文与译文）
dict.json       # 词典
lemma.json      # 词形
```

它们由内容流水线生成（`build_mobile_data.py` 依赖语料与词典源），本仓库只包含消费它们的代码。没有数据时页面会停在启动页，这是预期行为。

## 三、版本号：三处必须一致

| 文件 | 字段 |
|---|---|
| `assets/www/app.js` | `APP_VERSION` / `APP_CODE` |
| `AndroidManifest.xml` | `android:versionName` / `android:versionCode` |
| `mobile/tools/build_apk.py` | `VERSION_NAME` / `VERSION_CODE` |

规则：

- 功能版本：`1.7.3` → `1.7.4`；
- 修 bug / 小改：`1.7.3` → `1.7.3.1` → `1.7.3.2`（四段号合法）；
- `versionCode` 每次构建**独立递增**，不复用。

`AndroidManifest.xml` 里的值是最终值，`aapt2 --version-code/--version-name` 不会覆盖它。曾经出现过“脚本与文件名改了、manifest 没改”，装到手机显示旧版本 —— 所以 `apk_check.py` 会从包内 badging 回读。

## 四、出包

```bash
cd mobile
PYTHONIOENCODING=utf-8 python tools/build_apk.py
```

流程：`aapt2 compile/link → javac → d8 → 打包 dex → zipalign → apksigner`，产物：

```
mobile/dist/闲读-<版本>-release.apk     # 有正式签名
mobile/dist/闲读-<版本>-debug.apk       # 无 keystore.properties 时
```

签名：

- 本仓库**不含** `release.keystore` / `keystore.properties`；
- 首次发布前运行 `python tools/make_release_keystore.py` 生成自己的密钥（随机口令写入 properties，不打印）；
- 之后每次构建自动读取；密钥丢失意味着老用户无法覆盖升级，务必备份。

## 五、包内自检

```bash
cd mobile
python _test/apk_check.py
```

检查项：

| 项 | 失败意味着 |
|---|---|
| 包在不在、大小 | 构建没产出 |
| `classes.dex` | Java 没编进去 |
| badging 包名/版本 | 版本三处不一致 |
| `app.js` / `app.css` / `index.html` / `articles.json` 的 MD5 | 包内资源与源码不一致（最常见：改完没重打） |
| `TTS_SERVICE` queries | Android 11+ 找不到语音引擎 |
| `WebPageActivity` / `ApkProvider` / `REQUEST_INSTALL_PACKAGES` | 站内网页或应用内安装失效 |
| ES5 违规 | 用了 WebView 不支持的语法 |

**体积不变不代表没更新**：资源是压缩存储，正文小幅增删时 APK 字节数可能几乎不动。以包内资源 MD5 和条数为准。

## 六、UI 探针

探针不是单元测试，而是“把真实页面跑起来，用真实触控操作，再读 DOM / 量帧”。

### 启动静态服务器

```bash
cd mobile/android/app/src/main/assets/www
python -m http.server 8765
```

必须是 `http://`，`file://` 下 `fetch` 数据会失败。

### 运行

```bash
cd mobile/_test
PYTHONIOENCODING=utf-8 python ui172_probe.py
```

### 清单

| 探针 | 断言 |
|---|---|
| `tok_probe.py` | 分词边界、撇号、划线坐标、长按选区、复制内容 |
| `dict_probe.py` | 联网词典桩、缓存、失败兜底 |
| `dict_quality_probe.py` | 随机词头开卡无“未收录”、中文反查、短语不拆、重音折叠 |
| `goal_highlight_probe.py` | 6 档目标逐词比对 DOM 的划线类 |
| `strip_follow_probe.py` | 拖动中 chip 选中态跟手，落位只变一次 |
| `contpill_probe.py` | 浮条两种形态、拖动、关闭、跨页 |
| `fc_anim_probe.py` | 复习卡升起/落下曲线，动画类播完即摘 |
| `frame_audit.py` | 各交互的帧间隔与主线程阻塞 |
| `resume_probe.py` | 冷启动续读、返回清状态、失效自愈 |
| `ui171_probe.py` | 列表/我的/镜像页的关键文案与跳转 |
| `ui172_probe.py` | 统计 7 天、番外入口关闭、设置图标 |

### CDP 的两个坑

1. **上一轮 Chrome 没退干净**：会连到旧页面，表现为“元素突然查不到”的假红。`cdp.py` 关闭时用 `taskkill /F /T` 杀进程树；手工排查时按命令行里的 `_test` 目录杀，并删 `profile/Singleton*`。
2. **CDP 往返被算进帧间隔**：早期 `frame_audit.py` 从 Python 侧交错触发/采样，量出过 872ms 的假卡顿。现在触发与采样都在页面内一次跑完。

## 七、发布

```bash
cd mobile

# 1) 预演：只校验，不上传
PYTHONIOENCODING=utf-8 python tools/release.py \
  --notes-file dist/notes-<版本>.md --dry-run

# 2) 正式发布
PYTHONIOENCODING=utf-8 python tools/release.py \
  --notes-file dist/notes-<版本>.md
```

`release.py` 的硬校验：

1. 版本号三处一致、格式合法；
2. APK 存在，包内 badging 与源码一致；
3. 包内 `app.js/app.css/index.html/articles.json` 与源码 MD5 一致；
4. 清单关键项齐全；
5. ES5 违规为 0；
6. 远端没有同名 tag / release（不覆盖）；
7. 上传后回读：tag、资产名、字节数、sha256、latest 指针。

任何一项不过就中止，不会留下半成品 release。

### 发布说明

- 一个版本一个 `notes-<版本>.md`；
- 只写用户能感知的改动，每条一句话；
- **不写**内部彩蛋、测试数据、未上线内容；
- 修 bug 的版本可以沿用上一个功能版的说明，但版本号与标题要对应当前版本。

## 八、真机验收

自动化探针覆盖不到的部分，仍需在真机走一遍：

1. 覆盖安装后打开，旧进度/生词本/划线是否还在；
2. 阅读页：点句、点词发音、长按划线、拖手柄、笔记保存；
3. 难度条：点选 + 左右滑动换档，选中框是否只变一次；
4. 复习：开始/结束动画，答对答错，例句回原文；
5. TTS：语速/音高、切后台、锁屏；
6. 更新：检查更新 → 下载 → 校验 → 安装。

发现问题时记录：机型、Android 版本、操作序列、期望/实际。UI 问题优先用录屏或逐帧截图定位，不靠文字描述猜。
