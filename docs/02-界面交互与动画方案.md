# 02 · 界面交互与动画方案

这套界面是给“单手、竖屏、日常碎片时间”设计的。原则只有四条：

1. **能点就不滑，能滑就不弹窗**；模态层只在长按菜单、词卡、设置里出现。
2. **动画只做“从哪来、到哪去”的交代**，不做装饰性位移。
3. **手指跟手优先于动画完整**：拖动中任何动画都必须让位。
4. **颜色只改字和边框，不铺大面积底色**；深色模式靠变量整体翻转。

所有时长与缓动在 `app.css` 顶部：

```css
--ease: cubic-bezier(.2,.8,.2,1);
--ease-io: cubic-bezier(.4,0,.2,1);
--t-push: 300ms;  --t-pop: 260ms;
--t-sheet: …;     --t-tap: …;      --t-veil: …;
```

---

## 一、页面转场：ghost 双层

`#view` 是唯一容器。切页时不能先销毁旧页再建新页，否则会闪白。做法：

1. 把旧页的子节点整体搬进一个绝对定位的 `.view-ghost`，停在原坐标、保留滚动位置；
2. `#view` 渲染新页，初始放在屏幕外；
3. 两层用同一套 keyframes 反向运动：旧页推出、新页推入；
4. 动画结束（`setTimeout` + `animationend` 兜底）再移除 ghost。

方向由 `viewSwapKind(prev, next)` 决定：

| 场景 | 方向 |
|---|---|
| tab → 详情/设置子页 | push（新页从右侧进） |
| 详情 → tab | pop（旧页向右退） |
| 设置子页 → 设置首页 | pop |
| 详情 A → 详情 B | 记住上一跳方向，形成一致的层级感 |

只有 `go()` 走双层转场；tab 之间是简单的 `slideTo`；文章内部（目录跳转、回到原文）不做整页动画，避免阅读位置被打断。

**踩坑**：转场动画没播完就开始拖动，动画类会盖住手势的 `transform`。所以 `swapStart()` 第一件事是摘掉 `anim-push/anim-pop`、清掉残留 ghost。

## 二、难度条：在 `#view` 之外

- 难度条 `#levelStrip` 是 `#view` 的兄弟节点。切档时 `#view` 整块重画，难度条只改 `.on` 类，不参与重排，所以不会跟着闪。
- 点 chip：立即选中、居中、渲染新档。
- 左右滑动换档：见下一节。
- 主题分类条（阅读列表第二行）相反：**不横滑、按屏宽换行铺满**，最多 9 颗也全部可点；两侧不做渐隐遮罩。
- 最后一档继续右滑，接到底部「复习」tab，形成“读完这一档 → 去复习”的自然路径。

### 滑动换档为什么曾经“A-B-A 来回跳”

旧实现里一次手势会在同一个 tick 内三次改写选中态：

```
swapStart → selectLevel(新档) → renderRead → renderLevelStrip(按新档)
          → 又按旧档画回（为了转场中显示旧页）
          → paintLevelStrip(旧档)
```

用户看到的就是“跳过去又跳回来”。

现在的约束：

- `swapStart` 用 `swap.snap` 冻结旧档的 chip 与滚动位置；
- 换档途中只按 `snap.level` 画，落位 `swapEnd` 才切新档并居中；
- 点 chip 路径传 `noCenter=true`，不参与“画回旧档”，所以点选不会 A-B-A。

## 三、跟手换档：状态机

阈值（`app.js` 3268 起）：

```js
SWAP_RATIO = 0.6   // 拖过 60% 屏宽算完成
SWAP_VEL   = 0.5   // 或同向速度 ≥ 0.5 px/ms
SWAP_DAMP  = 0.3   // 首页/末页继续向外拖的阻尼
SWAP_MS    = 200   // 落位动画
SWAP_LOCK  = 8     // 先走 8px 再判横竖
```

每帧只做三件事：

1. `swapTx(旧页, dx)`、`swapTx(新页, dx ± 屏宽)` —— 只改 `transform`；
2. 用 `swapWillCommit(dx)` 算“这一下会不会落位”，判定与 `touchend` 完全一致；
3. 只有结论翻转时才改一次 chip 的 `.on`，不重排 DOM，不滚动难度条。

抬手时 `swapSettle(commit)` 是权威：先按 `commit` 定住选中框，再走 200ms 补完剩余行程；`swapEnd` 提交才切档并居中，回弹则恢复快照。

**为什么选中框要跟手，而不是落位才跳**：真机上从“六级”滑回“四级”时，如果选中框等页面落定才补一下，观感像“滑完才反应过来”。跟手的成本很低（一次 class 切换），收益是手势和结果始终一致。

## 四、「接着读」浮条

一个元素，两种形态：

- **阅读列表页**：展开成卡片，显示封面/标题/进度，点一下直接续读；
- **其他页面**：缩成右侧窄条，不挡内容。

交互：

- 纵向拖动改位置，`cont_pill_y` 归一化到 0~1 存进设置；
- 可在「外观」里关闭（`cont_pill`）；
- 页面切换时浮条**完全不动**：`renderContPill()` 在 `swap.busy` 期间直接返回，落位后再同步形态。之前它跟着转场一起变，拖动时先变一半、回弹再变回来，看着就是闪。
- 阅读页 ↔ 其他页：原地交叉淡入淡出。旧做法是“滑出去 → 换形态 → 滑回来”，中间必然有一段空白，观感像消失了一下。
- 冷启动时优先恢复 `resume_stem`，浮条只是入口，不承担状态。

## 五、阅读器交互

| 手势 | 行为 |
|---|---|
| 点句子 | 跳到该句朗读锚点 / 显示译文（按当前开关） |
| 点单词 | 打开词卡；先尝试发音 |
| 长按 | 进入划线浮层，弹出菜单 |
| 拖两端手柄 | 扩展/收缩选区（热区 44px，可视圆点 14px） |
| 左右滑 | 跟手翻页（文章内不整页重绘） |

划线规则：

- 同句只保留一条笔记，重复划线合并；
- 选区跨段时拆成多个区间存储（`marks[].r`）；
- 偏移量以“段内字符”为单位，渲染时再映射到 DOM，避免每次重排导致偏移失效；
- 自动保存，节流 180ms。

**为什么不用系统选区**：Android WebView 的原生长按菜单不可定制，手柄热区小、样式无法统一，且会与“点词发音”冲突。所以自己实现了选区层与手柄。

## 六、复习页动画

- 点「开始」：卡片从下方升起（`translateY 26 → 0`，`opacity 0 → 1`）；
- 点「结束」：当前内容沉下去（`0 → 26`，`1 → 0`），落完回“今日”；
- 都用 `@keyframes` + `both`，**播完必须摘类**。否则 `fc-fall` 的 `both` 会把下一页钉在 `opacity:0`，出现“点了没反应”的假死。
- 复习卡的答问切换只做淡入/轻微位移，不做翻转 3D：小屏上 3D 翻转的中间态会露出背面的字。

`fc_anim_probe.py` 逐帧验证两点：位移曲线是不是从 26 到 0；动画类是否在结束后被摘干净。

## 七、搜词：输入不重绘整页

复习页的搜索框同时支持英文和中文：

- 每次 `input` 只重算建议列表，然后只更新建议区 `#fcSug`，**不重绘整页** —— 否则输入框会丢焦点、光标跳到末尾；
- 英文：前缀匹配 + 重音折叠（`cliché` → `cliche`）；
- 中文：在释义里反查，按“义项边界 + 词性 + 词频档 + 考试档”排序，避免生僻词压过常用词；
- 固定短语（含空格/冒号）作为一个整体键参与匹配，不拆词；
- 回车直接打开第一条；没有结果不做跳转。

## 八、性能手法

| 手法 | 用在哪 | 原因 |
|---|---|---|
| `content-visibility: auto` | 581 篇书架、长列表 | 离屏行跳过布局和绘制 |
| 只动 `transform/opacity` | 转场、跟手、浮条、卡片 | 不触发 layout/paint |
| 启动时快照尺寸 | 跟手路径 | touchmove 里读 `clientWidth` 会强制同步布局 |
| 缓存词性/划线结果 | 正文渲染 | 同一页重复渲染不重算 |
| DOM 局部更新 | 搜索建议、进度、浮条 | 避免整页 `innerHTML` 丢焦点 |
| 分帧渲染 | 首屏 | 先出列表，再补统计/浮条 |

验收方法见 `04-构建-测试-发布.md` 的 `frame_audit.py`：在页面内一次触发交互并采样 rAF，避免 CDP 往返被误算成卡顿。

## 九、深色模式与视觉一致性

- 颜色全部走 CSS 变量，`setTheme` 只切 `data-theme`；
- 深色下金属流光档位单独提亮，不做简单反色；
- 卡片、浮层、菜单共用同一套圆角/阴影/背板变量，避免“每个页面一套皮肤”；
- 图标是内联 SVG（`ICON` 表），不额外发请求，也保证深色下 `currentColor` 跟随；
- 文案保持书面、简短；按钮不加口语化提示。
